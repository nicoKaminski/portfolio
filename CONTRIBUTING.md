# Cómo contribuir

Este repositorio contiene el código de mi Portfolio profesional personal, disponible en [https://nicokaminski.com/](https://nicokaminski.com/).

Se agradecen los reportes de problemas y las propuestas que ayuden a mejorar el sitio. Toda contribución está sujeta a revisión y su aceptación depende del mantenedor.

## Contribuciones bienvenidas

- Reportes y correcciones de errores.
- Mejoras de accesibilidad y experiencia de usuario.
- Correcciones ortográficas, enlaces rotos y otros problemas de presentación.
- Mejoras puntuales de rendimiento, responsive y animaciones.
- Sugerencias técnicas que faciliten el mantenimiento del sitio.

## Decisiones reservadas al mantenedor

El Portfolio representa mi identidad y trayectoria profesional. Por ese motivo, la selección de proyectos, las descripciones profesionales, la identidad visual y las decisiones generales de diseño quedan bajo mi criterio.

No agregues proyectos, modifiques información profesional ni introduzcas cambios visuales importantes sin aprobación previa.

Las propuestas que incorporen dependencias nuevas, servicios externos o cambios de arquitectura también requieren una consulta previa.

## Cómo reportar errores o sugerir mejoras

Utilizá la sección **Issues** de este repositorio y seleccioná el formulario correspondiente:

- **Reportar un error:** para problemas de funcionamiento, diseño, accesibilidad o textos.
- **Proponer una mejora:** para sugerencias de experiencia de usuario, rendimiento, animaciones u otros aspectos del sitio.

Antes de abrir un nuevo Issue, comprobá si ya existe uno sobre el mismo tema.

## Cómo proponer cambios de código

1. Para correcciones pequeñas y concretas, podés abrir directamente una Pull Request.
2. Para cambios visuales relevantes, nuevas funcionalidades o modificaciones de arquitectura, abrí primero un Issue y esperá la aprobación de la propuesta.
3. Prepará los cambios en una rama de tu fork del repositorio.
4. Abrí la Pull Request seleccionando `dev` como rama de destino.
5. Explicá qué modificaste, por qué y qué validaciones realizaste. Si cambiaste algo visual, incluí capturas cuando ayuden a revisar el resultado.

Las contribuciones deben ser puntuales y mantenerse dentro del alcance acordado. La presentación de una Pull Request no garantiza su aceptación.

No incluyas credenciales, información privada, material de terceros sin autorización ni contenido procedente de repositorios privados.

## Problemas de seguridad

Si descubrís una posible vulnerabilidad, no la publiques en un Issue ni en una Pull Request.

Seguí las instrucciones de [SECURITY.md](SECURITY.md) para enviar un reporte privado.
